# Tattoo Portfolio — Project Instructions

## Project Overview
Single-file HTML tattoo portfolio with rich animations and scroll effects.

**Stack:**
- GSAP + ScrollTrigger, via CDN
- Native scrolling — no smooth-scroll library (see **Scrolling**)
- No build step

## Core Rules

### File structure
- Every page is self-contained: inline `<style>`, inline `<script>`, no external local files unless explicitly requested. Shared chrome (tokens, nav, footer) is duplicated per page on purpose — there is no build step to share it.
- CDN links go in `<head>` before any scripts that depend on them.

### Theming (dark only)
- Every page carries ONE token block in its inline `<style>`: `:root`, which declares `color-scheme: dark`. Every surface colour comes from a token — never write a raw colour literal in a rule. There is no light palette, no `data-theme` attribute, no toggle and no `window.__theme`; the site was dark-only as of the light-theme removal and a second palette must not be reintroduced.
- Alpha surfaces compose from RGB-triplet tokens: `rgba(var(--panel-rgb),.88)`, `rgba(var(--fg-rgb),.07)`, `rgba(var(--gold-rgb),.4)`. `--on-gold` is the ink on a gold fill; `--ok*`/`--warn*` are the status colours; `--img-*` are the photo filters.
- `<meta name="theme-color" content="#0a0a0a">` is a static literal in each page's head. Nothing rewrites it at runtime.
- Chrome drawn over photography needs no token pinning: there is one palette, so `#loader`, `.wc-lbl`, `.wc-view` and `.pw-over`/`.pw-zoom` inherit the dark values. The subtree re-declarations that used to force this are gone — do not add them back.
- Never animate `backgroundColor` on `<body>` or any themed surface: an inline style outranks the tokens. Third-party brand colours (WhatsApp/Instagram/Facebook/Google) and black photo scrims are the only sanctioned literals.

### Responsive gutters
- One token owns the horizontal page gutter: `--pad` (`max(48px, calc(50vw - 720px))`, narrowed to `24px` by a single `@media (max-width: 768px) { :root { --pad: 24px; } }` right after the token block on every page).
- Section rules MUST write `padding: <v> var(--pad) <v>`, never a literal. Hardcoding it per-rule is how `.w-grid` drifted to 16px while every sibling sat at 24px.
- A `max-width`-capped child of a single-column grid needs `justify-self: center`, and a button stack inside an `align-items: flex-start` parent needs `width: 100%` — otherwise both shrink-wrap and read as drift.

### GSAP / ScrollTrigger
- Register all GSAP plugins at the top of the script: `gsap.registerPlugin(ScrollTrigger, ...)`.
- Pin sections with `ScrollTrigger` using `pin: true, anticipatePin: 1` to avoid jank.
- Use `ScrollTrigger.refresh()` after dynamic content loads or fonts are ready.
- Prefer `scrub: true` for parallax; use `scrub: 1.5` or higher for smoother feel.
- Never add a smooth-scroll library, and never drive the scroll position from a `gsap.ticker` callback — see **Scrolling**.
- Whole-document readouts (the progress bar, `/portfolio`'s nav-surface toggle) are a `ScrollTrigger.create({ start: 0, end: 'max', onUpdate })`, not a second scroll listener.
- Heading clip-path wipes (`.exp-h2`, `.tr-h2`, `.faq-h2`, `.bk-h2`) keep negative insets on the axes they do not animate, end past the box and `clearProps: 'clipPath'`. A resting `inset(0 …)` clips at the border box, and the italic serif descenders (`Q`, `y`, `p`) hang below a line-height-1 box — that is how they shipped cut off.

### Custom cursor
- Replace default cursor with CSS `cursor: none` on `html`.
- Use two elements: a small dot (instant follow) and a larger ring (lerp follow with `gsap.quickTo`).
- Add hover states on interactive elements via JS `mouseenter`/`mouseleave`.

### Particles
- Use canvas-based particles for performance.
- Cap particle count (≤150 on desktop, ≤60 on mobile).
- Pause/stop animation when tab is hidden (`visibilitychange`).

### Performance
- Use `will-change: transform` sparingly — only on actively animating elements.
- Wrap all animation setup in `DOMContentLoaded`.
- Debounce resize handlers; call `ScrollTrigger.refresh()` on resize end.
- Always test on mobile viewport (375px wide) — disable heavy effects on `(max-width: 768px)` if needed.

### Code style
- Keep page JavaScript inline. Dependency-free controls and state must initialize outside `__boot`; reserve `__boot` for GSAP/ScrollTrigger enhancement after both libraries are present.
- Group code by dependency boundary first, then by page feature. Scrolling is native — there is no scroll-library init step.
- Use `const` and arrow functions; no jQuery.
- Comment each major animation block with its section name.

## Validation and generated images

`scripts/check-balance.js` is the structural HTML check for all six pages. It uses the pinned `html-validate` 8.29.0 CommonJS API with `StaticConfigLoader`, the HTML5 element model and the explicit structural-rule set in the script; it is not a regex tag counter or a general styling/accessibility lint. Keep `scripts/check-inline-js.js` as the separate inline-script syntax check, and add every new page to both page lists.

Run `npm run check`, `npm test` and `npm audit --package-lock-only --audit-level=moderate` before shipping. The browser regressions use installed Chrome/Chromium/Edge or `CHROME_BIN`; never silently skip them. `.github/workflows/checks.yml` runs these checks on main pushes, pull requests and daily. Repository checks are not a deployment gate unless GitHub branch protection requires them; do not claim protection is configured without account evidence.

`npm run check:reviews-live` is a separate read-only production health check, also run by the daily/manual workflow. A provider outage must fail it even when saved reviews render correctly. GitHub notification delivery depends on the owner's notification settings. Never substitute a passing synthetic test for live-feed evidence.

When substantive page copy, links or structured data change, review that route's sitemap `lastmod`. Use the actual content-change date, not checkout mtime or every deployment date. Review Google feature claims against current official guidance; tests cannot establish that an external search feature still exists.

`_headers` is generated by `node scripts/make-security-headers.js`. After any inline-script change, regenerate it and commit the result; `npm run check` rejects stale hashes. The CSP is deliberately **report-only**, uses hashes for inline scripts and the existing `__libFail()` attribute handler, and allows inline styles for GSAP. Browser console violations are diagnostics, not evidence of enforcement or a remote reporting service. Do not switch to enforcement without exercising consent, galleries, menus, booking, Maps and Instagram.

The production `.com` zone has HSTS `max-age=31536000`, without `includeSubDomains` or preload, and the edge rule `canonical_www_to_apex` redirects `www.emmytattoo.com` to the apex with path/query preserved. `/api` and `/api/*` are excluded so API host/origin checks and request methods are unchanged. These account settings were verified on 24 September 2026; a checkout alone cannot establish that they remain active. `_headers` covers static assets, not Pages Functions.

Both image generators deliberately overwrite their derived outputs on every run. `scripts/make-webp-variants.js` regenerates responsive portfolio WebPs without enlargement, and `scripts/make-avatar-thumbs.js` regenerates the 96×96 cover thumbnails. Never add an output-exists/mtime cache, delete authored originals, or fold avatar generation into `npm run build:images`.

`pictures/Tattoos 2026/` holds renamed, byte-identical tattoo originals (JPEG, PNG and real HEIC; extensions match payloads) plus `catalog.json`, the authored record of each photo's `styles`, visual `healing` assessment (`fresh-looking`, `healed-looking`, `uncertain` — appearance only, never a claim of elapsed time), `publish`, `assetBase` and `alt`. The WebP generator reads flat `pictures/*.{jpg,jpeg,png}` and then every `publish: true` catalog row, decoding HEIC in memory through `heic-convert`, honouring EXIF orientation and stripping metadata. One published row per tattoo: alternate encodings/angles stay `publish: false` and produce no WebPs. Ten rows deliberately keep the old flat asset bases so existing URLs stay stable; any other flat/catalog base collision, duplicate base, missing source or invalid style/healing value fails the run. The catalog is build input only — never fetch it from a page. `.gitignore` excludes `*.HEIC`, so the 16 HEIC originals exist only on the working machine: a fresh checkout serves the committed WebPs fine, but `npm run build:images` there fails with `Missing selected image` until those files are copied back in. Do not force-add them.

## Shipping work

Work that came in as an approved plan ends with a push. Once the plan's steps are done and verified, commit and `git push` to `origin main` without being asked again — the live site is `main`, so unpushed work is work that does not exist. Do not stop at "committed", and do not wait for a second go-ahead.

Never commit `.claude/settings.local.json`, and never move `latest-stable` as part of shipping; that branch only moves on an explicit instruction.

## Stable snapshot

`latest-stable` is a branch that points at the last known-good commit of `main`.

- Mark the current `main` as stable: `git branch -f latest-stable main && git push -f origin latest-stable`
- Restore the site to it: `git fetch origin && git reset --hard origin/latest-stable && git push --force-with-lease origin main`
- Inspect it without moving anything: `git log --oneline origin/latest-stable -5`

The live site is whatever `main` points at, so restoring means force-moving `main` back onto `latest-stable`.

Google Analytics 4 is retained behind explicit opt-in on the five non-booking pages. No tag, analytics request or consent-mode ping may run before acceptance; time, scrolling and ordinary interaction are not consent. Each page duplicates the same dependency-free inline controller and neutral `.analytics-panel`, with equally prominent Accept/Reject buttons. `Cookie settings` reopens it from the footer. The booking page must not load GA or any replacement analytics, even after acceptance elsewhere: its transient health screening and prefilled blood-thinner discussion link stay outside site measurement. Cloudflare's automatic Web Analytics injection was disabled on both zones on 24 September 2026 because it bypassed this boundary; keep it disabled. The controller skips localhost, selects `G-M23QSCSBZ9` on `.co.uk`, otherwise `G-J8X45ECTLH`, and disables Google Signals and advertising personalisation. Keep `/legal` aligned with the actual consent/storage behavior. Do not enable metered services, billing, upgrades or paid add-ons to restore reviews without explicit owner approval; saved reviews remain the working fallback.

## Nav

The nav is bare over the hero and becomes a bar — blurred surface, bottom border, `Emmy Tattoo` wordmark at top left — exactly when the first section seam (`#work`'s top border) reaches it. That swap is a `ScrollTrigger` on `#work-outer` with `start: 'top <--nav-h>'`, not a scroll-offset threshold: `#nav` owns `--nav-h` (94px desktop, 78px at ≤768px) and the trigger re-reads it on every refresh, so the breakpoint needs no second number. `.n-logo` is `opacity: 0` until `#nav.s`; it keeps its box either way, so nothing shifts. `#nav` has no `::before` scrim — over the hero the nav sits on `.hero-bg-photo::after`, and `#nav:not(.s) .n-item` carries the hero text-shadow plate. `html.libs-failed` and the `<noscript>` block pin the bar on, because with no scroll observer the alternative is a nav that never gets a background.

Every nav icon sits on one 16px rhythm: `#nav { gap: 16px }` and `.n-actions { gap: 16px }` with no `margin-left` on `.n-actions` — that margin plus a 26px nav gap is what once left the theme toggle 42px from Facebook. Text links keep `.n-links { gap: 26px }`.

## Scrolling

**Scrolling is native. There is no smooth-scroll library and none may be added back.** Lenis was removed because it drives the scroll position from main-thread JS on every frame, which takes Chrome off its compositor-thread scrolling fast path for the whole document — the site felt like low FPS throughout on a 32-core machine where the `lite` heuristic never engages. `index.html` and `portfolio.html` load GSAP and ScrollTrigger only; ScrollTrigger listens to real scroll events, `scrub` still works, and the browser's own PageUp/PageDown/Home/End/space/arrow handling is back, so the hand-rolled keyboard pager both pages used to carry is gone with it. The two places that scroll for the visitor — anchor clicks and the `location.hash` deep-link after the loader — call `scrollIntoView({ behavior: SMOOTH, block: 'start' })`, where `SMOOTH` is `'auto'` under `prefers-reduced-motion`.

**The scroll lock is owner-based and available at parse time.** `index.html` and `portfolio.html` define `window.__scrollLock = { acquire(owner), release(owner) }` in a top-level `<script>` in `<head>`, backed by a `Set`; duplicate acquire/release calls are harmless and `html.locked` reflects whether any owners remain. Modal roots are owners and the home loader uses the literal `'loader'`. Never add counter/reset aliases or clear unrelated owners from a watchdog. `html` keeps `scrollbar-gutter: stable`, so locking does not shift the page.

**All menus and modal-style viewers use the shared inline `window.__ui` controller.** Direct-body `.ui-modal` roots start `hidden`, `inert`, `aria-hidden="true"` and own dialog semantics; the controller alone owns modal locks, stack order, background inert snapshots, focus containment/restoration, Escape/Tab behavior and transition cancellation. Visual transition adapters never manipulate locks or focus. Keep ordinary menus, galleries/lightboxes, reviews and accordions in once-only dependency-free initialization outside `__boot`; `__boot` may only add animation enhancements after both GSAP and ScrollTrigger exist. A failed CDN, reduced-motion change, hidden document or interrupted transition must still settle to a usable, unlocked state.

## Attention budget

The page spends attention in one direction: ask → work → proof → detail → ask again. Enforced by three rules.

1. **The hero asks, in two buttons.** `.h-cta` holds `Send an enquiry` (`.h-btn-go`, flat `--gold` with `--on-gold` ink, to `/book`) and `View portfolio` (`.h-btn-alt`, a transparent `--photo-ring` hairline that turns `--gold-ring-h` on hover, to `/portfolio`); both are cross-document navigations through `@view-transition`. The hero is centred — `#hero` and `.h-inner` both centre, and `.h-eyebrow` mirrors its gold rule with an `::after`, because a single leading dash reads as a stray mark once the line leaves the left rail. This replaced a deliberately CTA-less hero whose only affordance was a small `.h-scroll` cue; the change was made against direct competitor comparison and is not to be quietly reverted. Full-width buttons below 768px. The quiet contact is still the nav's Instagram/Facebook icons. `.h-loc-hours` carries `Appointment only · Tue–Sat`; its day range must stay in step with `openingHoursSpecification` in the `LocalBusiness` schema, while the opening and closing times deliberately live in the schema only and never in visible copy. `.h-eyebrow` reads `Fine line · Fine art · Realism` in the italic serif `.h-loc` uses, and there is no hero sentence: the one that stood under the wordmark repeated the eyebrow in a fourth typeface. `Directions` (`.h-dir`) is an underlined italic text link, not a chip.
2. **`#work` shows one row, then a gate.** `.w-grid` holds four interactive `.wc` cards in a 4-up grid (`.wc:nth-child(n+3)` is `display: none` at ≤1024px, where the grid is 2-up, so it is always exactly one row; ≤480px shows two stacked). Four columns shrink each card to ~327px at 1440, so the in-card chrome is sized to match (`.wc-lbl` `52px 14px 14px`, `.wc-view` 46px, its glyph 19px) and every card/peek `sizes` ends `25vw`. `.w-peek` follows: four `<img>` under `pointer-events: none`, clipped to `clamp(64px, 6vw, 96px)` and masked to transparent, with `.w-more` (gold ring, bobbing down-arrow, "View portfolio") pulled `-28px` up so it straddles the fade. They are cropped but they are not decorative — each carries the same alt text `/portfolio` gives the same photograph, and the wrapper is **not** `aria-hidden`, because four unnamed tattoos are four pieces of work a screen reader would otherwise never hear about. That gate is the only CTA in the section — never put a second button below the grid. Navigation to `/portfolio` is a native `@view-transition { navigation: auto; }` cross-fade declared in all four documents; never hand-roll it in JS.
3. **One left rail, three staged centres.** Every eyebrow, heading, paragraph and list starts at the `--pad` gutter so the eye learns one vertical line. `text-align: center` is allowed only for the hero (`#hero`), the booking close (`.bk-in`), and the work gate (a symbol on the fade's axis) — the reviews spotlight that used to hold the third slot is gone. `/book` is a fourth centred column, but it is a page of its own, not a fourth centred block on the home page; inside it the form is left-aligned (`.bk-form { text-align: left }`), because centred field labels are unreadable. `#flash` and `#gifts` were centred and are now on the rail; adding a fourth centred text block to `index.html` is a regression.

## Converting

Section order on the home page is `hero → work → trust → about → exp → faq → book → flash → location`. Reviews sit directly behind the work that earned them; the ask is at the bottom because the hero already offered it. Aftercare and gift cards used to sit between `book` and `flash` and are now `/aftercare` and `/gift-cards`: two subjects a visitor arrives searching for by name, which a mid-page section on a long home page can never rank for. Their CSS is prefix-namespaced (`.ac-*`, `.gf-*`) and moved with them, as did `--gc-ink`/`--gc-ink-wm`, whose only consumer is `.gf-card`. FAQ 03 links out to `/aftercare` through a `.fq-answer-link` **sibling** of `.fq-answer` — never inside the answer, which has a word-for-word twin in the FAQPage schema.

- **Reviews are a grid, never a carousel.** `#tr-stage` is `repeat(3, 1fr)` (2-up ≤1024, **2-up ≤768**) of `.trv-card`, with `--tr-gap` owning the gap so the phone tip can size itself off it. Google's Places API returns **at most five** reviews, so `roster()` takes the live five and tops up from `SEEDED` — seven transcribed from the same listing — de-duped by lowercased name, to fill **seven**. Preserve these saved reviews; five is the API sample limit, not the listing's total. The seventh is `display: none` above 768px, because six fill the 3-up and 2-up grids exactly and a seventh would strand a card on its own row; on phones it lands alone and `:last-child:nth-child(odd)` centres it at one column's width — the tip. A "read full review" button is rendered on every card and then **hidden where the clamp actually did not bite** (5 lines on phones, 6 above), measured after `document.fonts.ready`. Hidden, not removed: a debounced resize re-runs `prune()` and can bring it back. Click/keydown handlers bind once behind `dataset.clamped`; `.trv-more[hidden]` must override `display: inline-flex`. All untrusted fields use DOM text/property assignment, never HTML interpolation.
- **The review badge keeps its five gold stars.** Until a valid feed arrives, the label is `5-star Google reviews`, as explicitly requested; never replace it with `Selected Google reviews`. The saved reviews remain visible, while the overall numeric rating/total waits for a valid feed. Do not reintroduce numeric fallback counts or an unverified static `aggregateRating`. The Worker source lives in `workers/reviews/`; deploy it separately with `npx --yes wrangler@4.138.0 deploy --config workers/reviews/wrangler.jsonc`, preserving the existing `GOOGLE_KEY` secret. Provider failures return non-200, log safe status information for the owner, and never publish raw Google diagnostics. Google project permissions and billing are external prerequisites, not something a front-end fallback can repair.
- **The ask lives on `/book`, not on the home page.** `#book` on `index.html` is a pitch that ends in one `.bk-cta` — a `Send an enquiry` anchor to `/book` plus a one-line note — and the hero's `Send an enquiry` goes straight there too. Both are cross-document navigations that `@view-transition { navigation: auto; }` fades exactly like `/portfolio`. The `#book` id stays because five ScrollTriggers use it as a trigger; nothing links to it any more.
- **`book.html` loads no GSAP and no loader, on purpose.** It is built from `legal.html`, the original CDN-free shell, so the one thing on the site that must never break depends on nothing off-origin. `aftercare.html` and `gift-cards.html` are built from the same shell for the same reason. Do not add the animation bundle to any of them. Because they have no reveal animations they need no `noscript` / `libs-failed` / `prefers-reduced-motion` fallback list — the three lists in `index.html` are still a matched set and still have to be edited together.
- **The enquiry form hands off to WhatsApp.** Submit composes a prefilled `wa.me/447405979137?text=…` message and opens it; the visitor presses send in their own client, and Emmy's Business-app greeting then asks for reference photos, which they attach natively in the chat. **The page never touches photos.** `wa.me` cannot carry an attachment and `navigator.share()` cannot preset a recipient, and the Cloud API workaround that preceded this — Emmy's own number sending the client their own photos back — read as a glitch and put her working number in Meta's enforcement path. Photos are Emmy's side of the problem, not the site's. There is no Meta account, no template, no token and no media upload anywhere in this repo; do not reintroduce one.
- **Health screening gates the enquiry without becoming enquiry data.** On initialization, pregnancy is asked first. `yes` stops the enquiry; `no` reveals the blood-thinner question. Blood-thinner `yes` keeps the form closed and offers only the user-activated WhatsApp discussion draft; only explicit `no` answers to both questions enable the form. These answers are transient: never put them in the form, backup, storage, cookies, web storage, URL/history or analytics, and reset them on initialization and persisted `pageshow`. General medical information belongs in a visitor-sent WhatsApp conversation, not the website backup.
- **The deposit block is config-gated.** `DEPOSIT = { url, amount }` at the top of the enquiry script in `book.html`. Empty `url` keeps `#bk-dep` hidden; set it to a Stripe Payment Link and the block appears with `Pay <amount> deposit`. No keys, no backend, no half-built button on the page.
- **`FIELDS` owns the normal WhatsApp message order, labels and UTF-16 caps.** The order and caps are name 40, email 70, idea 300, placement 40, size 40, budget 20, availability (`when`) 50, notes 150 and reference link 100. Normalize whitespace and validate once; reject over-cap or malformed-surrogate input without changing the editable value. `MSG_MAX` is 1000 and `URL_MAX` is 8000. Values total at most 810 units, the current scaffold adds 139, and the conservative encoded bound is 7739; never truncate a field, complete message or URL to fit. If the skeleton or fields change, recompute both budgets.
- **Notes are WhatsApp-only.** They remain in the visitor's WhatsApp draft but are excluded from the website backup. Never claim that all other free text is medically filtered, and never add notes or either screening answer to the API contract. Field order remains name, email, idea, placement, size, budget, when, notes, refs; email stays second as the fallback channel.
- **The 18+ tick is a legal gate.** `.bk-form input` has equal specificity and comes later, so `.bk-form .bk-f-chk input` plus an explicit `appearance: checkbox` is required or it renders as a full-width empty rectangle with no tick. Verify it in a screenshot, not by reading the CSS — that is how the bug shipped once.
- **`/api/enquiry` is a strict best-effort backup, not delivery.** The browser allowlists exactly name, email, idea, placement, size, budget, when and refs, then adds literal `age18: true` and boolean `botcheck`; it tries `sendBeacon`, falls back to non-blocking keepalive `fetch`, and never awaits either before the synchronous WhatsApp open. The endpoint rejects unknown keys, wrong types, non-canonical select/day values, malformed text and requests over 16,384 actual body bytes. It stores only approved nonempty strings plus server timestamp/country for 90 days; never age, honeypot, notes, screening answers or inferred health clearance. Missing KV, honeypot-positive input and failed writes remain `200 {stored:false}`. Keep `book.html`, `functions/api/enquiry.js` and `/legal` in step; old backups may retain formerly submitted notes only until their original expiry or an individual deletion request.
- **The endpoint has two separate origin boundaries.** The request URL host and a present `Origin` must each be in the exact production allowlist (`https://emmytattoo.com`, `https://www.emmytattoo.com`) or an explicitly configured protected `ALLOWED_ORIGIN`; never wildcard Pages previews or trust forwarding headers. This gate also applies to OPTIONS.
- **Cloudflare edge rate limiting is a deployment requirement, not repository state.** Do not claim it is active without account/rule and live-response evidence. The required rule is named `Enquiry backup burst protection`, matches `(http.request.uri.path eq "/api/enquiry" or starts_with(http.request.uri.path, "/api/enquiry/"))`, counts by `ip.src` plus `cf.colo.id`, and blocks after 5 requests in 10 seconds for 10 seconds with the default 429 response. It must cover both production hosts with no earlier skip exemption; reuse only an existing rule dedicated to this endpoint and never substitute a process-local/KV limiter or CAPTCHA.
- **`<select>` is the one form control that must not be translucent.** Chrome and Edge paint the native option list from the control's own used `background-color`, and the `.03` wash every other field uses composites against the popup's default white — that shipped a white list with near-white `--fg` text, i.e. a budget you could not read. `--field` (`#111111`) is that wash already resolved over `--bg`, so the field looks identical on the page and the popup is legible; `option` is painted explicitly as well because Firefox reads option colours instead. The `:focus-visible` rule is split for the same reason: `select` gets the gold ring only, never a translucent fill.
- **Dependency-free interactions must never move into `__boot`.** The shared `window.__ui`, menus, work/skill/portfolio viewers, FAQ/expertise accordions, reviews, loader completion, embeds and portfolio filtering/batching all remain usable without GSAP or ScrollTrigger. They read optional animation globals at call time. `__boot` guards on both libraries and owns animation enhancement only; it may call the one-shot `window.__portfolioGrid.enhance()` but must not rebind controls or become their availability boundary.
- **`/portfolio` renders 12 pieces at a time** behind `#pw-gate`, a `grid-column: 1 / -1` child holding `.pw-more`, which reveals the next 12, reports the remainder, hands focus to the first new card with `preventScroll`, and hides itself when the matched set runs out. Filtering resets to the first batch. `#pw-gate[hidden]` is restated in CSS because `display: flex` on the same element outranks the UA rule. A filter button that matches nothing hides itself. Filters are `all`, `fine-line`, `fine-art`, `realism`, `illustrative`, `ornamental`, `lettering` and `healed`; `data-style` is whitespace-separated membership, so one card sits in several filters without being cloned (the tiger is `realism healed`). `healed` is added only for catalog rows marked `healed-looking`, and `.pw-healed` is the always-visible gold chip (unlike the hover-only `.pw-tag`) on those cards. `#filter-bar` is not sticky: it sits in normal flow above the grid and scrolls away with the page. Pinned under the fixed nav it left a strip of photos showing between the two bars, so never make it sticky again.
- **Homepage schema has two blocks.** `TattooParlor` carries `founder` (Person); a second script carries `FAQPage`. Keep the six question/answer strings word-for-word aligned with visible `#faq` copy. Google retired FAQ rich results in May 2026; this markup is descriptive, not a promise of a search feature. Google also excludes self-serving local-business review stars. There is no static `aggregateRating` while the listing total is unverified, and no `<meta name="keywords">`.

## Third-party embeds

Every iframe on the site is injected by one loader — the standalone `<script>` after `__boot`'s block, deliberately outside `__boot` because that function returns early when the CDN libs fail and a map must not depend on a CDN. A container opts in with `data-embed="<url>"` plus optional `data-embed-title`, `data-embed-scroll="no"`, and gets its iframe from an `IntersectionObserver` at `rootMargin: '600px 0px'` (one screen of warning), marked `data-embed-loaded="1"`. There is no click-to-load facade and no "Load map" button; never reintroduce one. Two consumers today: `#loc-map-wrap` and `.fl-ig-frame`.

- The map embed takes **coordinates** (`?q=53.7558,-0.3587&output=embed&z=17`), not the address string: the `?q=<address>` form opens with a permanently blank white place card over the map. The address is set in type above it, and the four Navigate buttons handle routing. `#loc-map-wrap` also carries a `<noscript>` copy of the same iframe, so a JS-less visitor still gets a map.
- Google's `output=embed` map does **not** trap the wheel (vertical scroll passes through to the page; zoom needs ctrl), so the iframe stays fully interactive with no click, hover-dwell or `pointer-events` gate. Measured, not assumed — if you ever change the embed URL, re-measure before adding a gate.
- The Instagram panel is Instagram's own profile embed (`/emmy.tattoo/embed`) — always current, no post IDs to maintain — but it is **cropped to its photo grid**, because the widget is white in every theme: `?theme=dark`, `?cr=1&theme=dark`, `prefers-color-scheme: dark` emulation and a `Sec-CH-Prefers-Color-Scheme: dark` request header all return the same white page, `/embed/captioned/` is not valid for a profile URL (it renders the "Page isn't available" shell, which is the only reason a dark background ever appears), and oEmbed exposes `maxwidth`, `hidecaption` and `omitscript` only. `filter: invert()` would negate the photographs too.
- The crop: `.fl-ig-panel` owns the border, radius and `--bg2` surface; `.fl-ig-frame` is `aspect-ratio: 3/2` with `overflow: hidden`; the iframe inside is absolutely positioned at `top: -147px` with `height: calc(100% + 197px)`, which pushes the 147px white header and the 49px "View full profile" band outside the clip. Measured against the live embed: three columns of `(W-2)/3` with 1px gutters, two rows, so the grid is exactly 2/3 of the width — `aspect-ratio` gets that in every browser, which is why no container query is needed and `.fl-ig` no longer sets `container-type`. `.fl-ig-frame::after` paints the embed's 1px white gutters out with two repeating gradients at period `tile + 1px`. Every tile anchor in the embed is `href="#"`, so the crop costs no interaction, and `.fl-ig-cap` carries the attribution link the cropped footer used to provide. If Instagram changes its chrome, re-measure and fix those two numbers — never fall back to showing the white widget.

Both sides are `aspect-ratio: 5/3` so the row ends level; `.loc-photo` needs an explicit `height: auto`, because the `width`/`height` attributes are presentational hints and `aspect-ratio` is ignored while both axes are specified. `.loc-photo` reveals with `.loc-map-wrap` in one tween and is listed in all three reveal-fallback selector lists.
- `#gifts` — the whole of `/gift-cards` — is a two-column row: copy on the `--pad` rail in a `flex: 0 0 clamp(320px, 34%, 520px)` column, the voucher filling the rest out to the right gutter. The voucher is **not an `<img>`** — `.gf-card` is an empty `role="img"` div at `aspect-ratio: 1091/494` whose `background` is a token and whose `mask-image` is `pictures/web/Emmy-Tattoo-Gift-Card-Voucher-Ink.webp`, a lossless alpha-only mask lifted from the grey artwork (`sharp().greyscale().linear(-255/162, 255*190/162)`: paper ≈ grey 190 → alpha 0, ink ≈ 28 → alpha 255). Painting the artwork from a token is what lets one asset read with no `filter`, and it is why the section needs no `overflow: hidden` on desktop and the card no rotation, stroke or edge fade. The mask lives in `pictures/web/` so `make-webp-variants.js`, which only reads `pictures/*.{jpg,png}`, never re-encodes it lossily.
- At ≤768px that voucher stops being a block and becomes the section's watermark: `#gifts` goes `position: relative; overflow: hidden`, `.gf-body` takes `z-index: 1`, and `.gf-card` is absolutely positioned at `left/right: -8%`, vertically centred, painted `--gc-ink-wm`. As a 342×155 block under the CTA it read as a floating smudge with dead space around it.
- The expertise rows reuse the FAQ accordion wholesale: `<li class="ei">` with a hairline `border-top`, a `<button class="ei-trigger">` (title + circular `.ei-toggle` that CSS-rotates 45° when open), an absolutely positioned `.ei-rule` gold sweep whose width GSAP animates (60% open, 30% hover), and the `height: 0` panel measured and tweened exactly like `.fq-panel` (0.55 expo.out / 0.35 expo.in). Same mechanic, same width: `.exp-list` carries **no `max-width`**, so the `.ei` hairlines are exactly as long as the FAQ's `.fq-item` hairlines (1344px at 1440) and both toggles pin to the same right edge. The measure is protected by `.ei-expand-text`'s own `50ch` cap and the panel's fixed 240px image column, never by capping the list. There are no per-skill summary lines, no numerals (numbering three styles reads as a ranking), no card border and no hover timeline — the old GSAP `x`/`color` timeline was the only writer of inline colours in the section, which is why the theme toggle no longer needs a `clearProps` call. The accordion listens on `.ei-trigger`, not the `<li>`, so `.ei-see-more` inside the panel needs no `stopPropagation` and opening the gallery cannot collapse the row.
- `/portfolio` is a uniform 4-up grid, not masonry: `#pw-grid` is `display: grid; grid-template-columns: repeat(4, 1fr); gap: 12px` (2-up at ≤1024px and at ≤768px), every `.pw-item` is `aspect-ratio: 3/4` and every image is `height: 100%; object-fit: cover`. The gallery holds 55 static cards, one per published catalog row, with the water-lily close-up first and eager; every `sizes` is `(max-width: 480px) 160px, (max-width: 1024px) 50vw, 25vw`, and `width`/`height`/`srcset` descriptors are the real decoded 960/480 variant sizes. The `ImageGallery` schema and the `/portfolio` `<image:image>` sitemap entries list exactly the same 55 canonical 1440 WebP URLs in card order — change all three together. The lightbox reads each item's live rect at click time, so it needs no changes when the grid does.
- The gallery renders **12 pieces at a time** behind `#pw-gate` — a `grid-column: 1 / -1` child of the grid holding a `.pw-more` button that reveals the next 12, reports how many are left, hands focus to the first new card (`preventScroll`, so the browser does not yank the page to it) and hides itself when the matched set runs out. Changing a filter resets to the first batch. `#pw-gate[hidden]` must be restated in CSS: `display: flex` on the same element outranks the UA's `[hidden]` rule. Filtering and batching live in **one top-level script under the grid, never inside `__boot`** — `__boot` returns at its lib guard when the CDN bundles fail, and the gallery must survive that — and the script reads `window.gsap` at call time, not at init, because the deferred bundles have not executed when it first runs. Hiding is by `display`, which is why the three `opacity` reveal-fallback lists need no entry for the gate. The lightbox is untouched: `vis()` reads `.pw-hidden` off the live DOM.

The ≤1024px stack re-declares `align-items: stretch`, or the copy column would shrink-wrap and leave the rail.

## Design Aesthetic
- Neutral `#0a0a0a` dark, the only scheme; gold is the single accent
- No `sepia()` in any `--img-*` filter: it emits R>G>B and the `brightness()` that follows clips red first, so a full-viewport photo's highlights converge on olive (measured: the hero's brightest decile carried a +0.42 green hump, now −0.05). Warmth comes from `--ambient-hero`, which cannot skew channels.
- Gold is ONE token, `#c4a262` — `--gold` / `--gold-rgb: 196,162,98`. There is no `--gold-display` and no second gold; never reintroduce one. Small mono labels and tiny links use `--fg`/`--fg2` and carry gold as a rule (`.h-eyebrow::before`), ring, border or glyph. Gold text is allowed at display sizes (`em` accents in headings, hero title, `.ft-logo`, `.bk-step-n`); icon/star/arrow glyphs keep gold at any size. Section eyebrows (`.s-label`) are gone — headings lead
- The homepage availability label (`.bk-av`) is a serif ornament, not a status capsule: off-white italic `Diary open` between two 28px gold pseudo-element rules, with 14px gaps and 40px below it. No dot, glow or continuous pulse. `DIARY_OPEN = false` changes the wording to `Diary closed` and only the rules to `--warn`; the enquiry CTA stays available. Preserve the existing scroll entrance and all three reveal fallbacks.
- **Every gold call-to-action is a square serif button.** `.n-book`, `.h-btn`, `.bk-f-btn`, `.tr-review-btn`, `.pw-more`, `.pf-proof-all`, `.bc-btn` and `.gf-cta` share one face per page (`border-radius: 0`, `var(--serif)` italic 400, `letter-spacing: .01em`, no uppercase). There is no pill, no drop shadow and no hover lift: a solid gold hover brightens through `--cta-wash`, never through `--gold-soft`, and a press sinks 1px. The pill-and-glow treatment that preceded it was rejected as reading cheap. `.fl-cta` (Follow on Instagram / Facebook) and `.loc-btn` (the four travel buttons) are the neutral tier of the same face: a `--border-h` hairline and `--fg` label at rest, a gold focus ring, a 1px press. Their hover is the one place a button shows brand colour — `.fl-cta-ig` the Instagram gradient wash, `.fl-cta-fb` Facebook blue, `.loc-btn-waze` cyan, `.loc-btn-gmaps` the four-colour Google border, `.loc-btn-transit` a blue-to-green border, `.loc-btn-uber` a neutral lift. A uniform gold hover was tried on all six and removed: it stripped the sections of personality.
- **The gold italic `<em>` in a heading marks one word per title.** It appears in the nav and footer wordmarks on every page, the hero `<h1>` on `/` (whose `<em class="tl-i">` is also the char-split animation hook — converting it to a `<span>` without also removing `index.html`'s `.h-title .tl-i { opacity: 0 }` rule leaves the hero permanently invisible), the home section headings (`Hi, I'm <em>Emmy</em>`, `Areas of <em>Expertise</em>`, `What clients <em>say</em>`, `<em>Frequently Asked</em> Questions`, `<em>Follow</em> the work`, `Send an <em>enquiry</em>.`, the `#location` address), `Send an <em>enquiry</em>.` on `/book`, the page titles `My <em>Work</em>` (`/portfolio`), `Keep it clean.<br>Let it <em>heal</em>.` (`/aftercare`) and `Give someone a <em>tattoo</em>.` (`/gift-cards`), and `/portfolio`'s closing `Enquire about your <em>piece</em>.`, each styled by its own `X em { font-style: italic; color: var(--gold) }` rule. `.lg-h1` stays plain. The display face has no italic, so `/portfolio`'s `.h-title` carries `word-spacing: -.2em` — the synthesized slant otherwise reads as a double gap before `Work`. Trailing punctuation lives **outside** the `<em>`: `<em>heal</em>.`, never `<em>heal.</em>` — a gold italic full stop is a typo the eye reads as a smudge. The `<span class="tl"><span class="tl-i">` wrappers are reveal-animation containers on four `index.html` headings and are unrelated to this device; never delete one to remove an italic.
- Decorative gold ink carries its alpha in a token, not in `opacity`: `--gc-ink` and `--gc-ink-wm` (`.gf-card`), because GSAP writes inline `opacity` that outranks CSS. Two tokens have been retired for lack of a user — `--ghost-ink` with the reviews spotlight and `--wm-ink` with the `Book` watermark — so do not reintroduce an unused one. The voucher runs at two weights, illustration beside the copy and watermark behind it on phones, and keeps gold at both (`.12` / `.10`).
- **A lone lowercase article in a heading is set in the heading's own face, at the heading's own size.** `.h-art` used to put it in `var(--display)` at `1.12em` to stop it reading as a speck, but all three headings that used it (`.bk-h2`, `.bk-page-h1`, `.gf-h2`) are Cormorant, not display: the article was the only letter being rescued from a low x-height its neighbours all share, and the swap plus the bump made it 1.35× the ink height of the word beside it (measured 23px against 17px at a 390px viewport). Cormorant's italic `a` still reads as an `@`, so an article must not be wrapped in the gold `<em>` either — leave it upright and plain.
- Decorative display type opts out of selection: `-webkit-user-select: none; user-select: none` on `.h-title`, `.h-eyebrow` and `.fq-num`. Selectable text accepts a text caret, so a visitor browsing with Chrome's caret browsing (F7) clicked the hero wordmark and got a blinking cursor sitting in it. Keep the opt-out to type nobody has a reason to copy — `.h-loc` (studio address and hours) stays selectable, and never reach for `caret-color: transparent` on `body` or any ancestor, which would blank the caret inside the enquiry-form fields and strip the navigation cursor from anyone using caret browsing deliberately.
- Every section divider is `border-top: 1px solid transparent; border-image: var(--seam) 1` — one token, one definition: `.16` ink flanks into a `.55` gold centre. Tune the token, and never hand-roll a divider gradient in a rule.
- Minimal UI — let artwork breathe
- Smooth, deliberate animations — nothing snappy or bouncy
- Monochrome or desaturated palette with one accent color
